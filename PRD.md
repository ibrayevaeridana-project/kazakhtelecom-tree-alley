# PRD: «Дерево жизни сотрудника»

## 1. Краткое описание

«Дерево жизни сотрудника» — локальный внутренний сайт для АО «Казахтелеком», посвященный экологической инициативе, в рамках которой каждый новый сотрудник до 35 лет после трудоустройства высаживает одно именное дерево.

Дерево становится символом начала профессионального пути сотрудника в компании. Со временем из таких деревьев формируется «Будущая Аллея Казахтелекома», которая в перспективе может стать корпоративным парком и масштабироваться на другие города Казахстана.

## 2. Цели проекта

- Поддержать экологическую инициативу «Таза Қазақстан».
- Внести вклад в озеленение города.
- Развивать экологическую культуру среди молодых сотрудников.
- Укрепить корпоративную культуру Казахтелекома.
- Создать живой символ причастности сотрудника к компании.
- Сформировать основу для будущей корпоративной аллеи или парка.

## 3. Целевая аудитория

- Новые сотрудники Казахтелекома до 35 лет.
- Сотрудники компании, участвующие в экологических инициативах.
- HR-подразделение.
- Руководители подразделений.
- Организаторы корпоративных мероприятий.
- Администраторы проекта.

## 4. Основной сценарий

1. Новый сотрудник устраивается на работу в Казахтелеком.
2. В течение года он участвует в акции по посадке деревьев.
3. Сотрудник высаживает одно именное дерево.
4. Информация о дереве заносится в локальный журнал проекта.
5. Сотрудник может зайти на внутренний сайт, найти свое дерево и посмотреть карточку «Дерево жизни сотрудника».

## 5. Формат проекта

Проект должен быть реализован как локальный HTML-сайт, который открывается на компьютере без сторонних серверов и сложной установки.

Рекомендуемая структура файлов:

```text
project/
├── index.html
├── style.css
├── script.js
├── data/
│   └── trees.json
└── assets/
    ├── images/
    ├── icons/
    └── maps/
```

## 6. Технические ограничения

Проект должен работать полностью локально:

- без сторонних серверов;
- без backend;
- без баз данных;
- без платных API;
- без подписок;
- без облачных сервисов;
- без обязательного подключения к интернету;
- без Google Maps, Яндекс Карт, 2GIS API и других внешних картографических сервисов;
- без внешних CDN;
- без внешней авторизации.

Все данные должны храниться в обычных локальных файлах, например `trees.json` или `employees.json`.

Сайт должен открываться двойным кликом по `index.html` в браузере.

## 7. Главная страница

На главной странице должны быть:

- название проекта: «Дерево жизни сотрудника»;
- подзаголовок: «Будущая Аллея Казахтелекома»;
- краткое описание инициативы;
- блок входа по ФИО и табельному номеру;
- общий счетчик посаженных деревьев;
- интерактивная карта или генеральный план зоны посадки;
- раздел «Найти свое дерево»;
- статистика по посадкам;
- журнал деревьев;
- переключатель между видом карты и 3D-аллеей.

Дополнительный вариант подзаголовка для презентационного режима:

```text
Будущая Аллея Казахтелекома — зеленый след каждого нового сотрудника
```

## 8. Авторизация

Авторизация должна быть условной и локальной, без внешних сервисов.

Пользователь вводит:

- ФИО;
- табельный номер.

После входа сотрудник должен увидеть:

- свое именное дерево;
- карточку дерева;
- расположение дерева на карте или генеральном плане;
- данные о посадке.

Важно: так как проект локальный и без базы данных, авторизация не является полноценной системой безопасности. Она используется как демонстрационный механизм поиска сотрудника в локальном файле данных.

## 9. Данные по дереву

Для каждого дерева должны храниться следующие данные:

- ID дерева;
- ФИО сотрудника;
- табельный номер;
- должность;
- подразделение;
- город;
- год посадки;
- период посадки;
- тип дерева;
- координаты на локальной карте или плане;
- статус дерева;
- фото посадки, если есть;
- заметка или описание.

Пример структуры данных:

```json
{
  "id": "tree-001",
  "fullName": "Иванов Иван Иванович",
  "employeeNumber": "KT-10234",
  "position": "Инженер связи",
  "department": "Технический блок",
  "city": "Астана",
  "plantingYear": 2026,
  "plantingPeriod": "Весна 2026",
  "treeType": "Береза",
  "status": "Посажено",
  "coordinates": {
    "x": 42,
    "y": 58
  },
  "photo": "assets/images/tree-001.jpg",
  "note": "Первое дерево сотрудника в рамках проекта."
}
```

## 10. Карта и генеральный план

Сайт должен содержать локальную карту или схему посадки деревьев.

Возможные варианты реализации:

- локальное изображение карты Астаны;
- SVG-схема зоны посадки;
- генеральный план будущей аллеи;
- условная схема корпоративного парка;
- локальная 3D-сцена аллеи.

Требования к карте:

- деревья должны отображаться как кликабельные точки или иконки;
- каждое дерево должно иметь именную подпись;
- при клике должна открываться карточка дерева;
- карта должна работать без внешних картографических сервисов;
- структура должна позволять в будущем добавить другие города Казахстана.

## 11. 3D-аллея

В проекте должен быть предусмотрен режим 3D-аллеи.

Требования:

- 3D-вид должен работать локально;
- деревья должны быть размещены в виде аллеи или парковой зоны;
- у каждого дерева должна быть именная табличка;
- при выборе дерева должна открываться карточка сотрудника;
- допустимо использовать локально подключенную бесплатную библиотеку, если она лежит в папке проекта;
- не использовать внешние CDN и онлайн-сервисы.

Если полноценная 3D-модель слишком сложна для первого прототипа, допустимо реализовать упрощенную псевдо-3D-сцену средствами HTML, CSS и JavaScript.

## 12. Карточка «Дерево жизни сотрудника»

Карточка дерева должна содержать:

- заголовок: «Дерево жизни сотрудника»;
- ФИО сотрудника;
- табельный номер;
- должность;
- подразделение;
- город;
- год посадки;
- период посадки;
- тип дерева;
- статус дерева;
- фото дерева или фото посадки;
- координаты на плане;
- короткую заметку.

Карточка должна выглядеть персонально, тепло и торжественно, но оставаться в стиле внутреннего корпоративного портала.

## 13. Журнал проекта

На сайте должен быть журнал всех деревьев.

Функции журнала:

- просмотр всех записей;
- поиск по ФИО;
- поиск по табельному номеру;
- фильтр по году;
- фильтр по городу;
- фильтр по подразделению;
- фильтр по типу дерева;
- отображение общего количества записей.

## 14. Статистика

Сайт должен показывать базовую статистику:

- общее количество посаженных деревьев;
- количество деревьев по годам;
- количество деревьев по городам;
- количество деревьев по подразделениям;
- количество участников проекта.

Статистика должна строиться на основе локального файла данных.

## 15. Дизайн

Дизайн должен сочетать экологическую тему и корпоративный стиль Казахтелекома.

Визуальное направление:

- современный внутренний корпоративный портал;
- экологичный, светлый и спокойный интерфейс;
- ощущение роста, чистоты, доверия и технологичности;
- акцент на человеке, дереве и вкладе в будущее.

Цветовая палитра:

- зеленый;
- светло-зеленый;
- белый;
- мягкий серый;
- бирюзовый или синий как корпоративный акцент Казахтелекома.

Визуальные элементы:

- листья;
- ветви;
- годовые кольца дерева;
- мягкие природные линии;
- аккуратные иконки деревьев;
- элементы, напоминающие карту, аллею или парк.

Интерфейс не должен выглядеть как рекламный лендинг. Он должен восприниматься как удобный внутренний сайт крупной телеком-компании.

## 16. Масштабирование

Первая версия проекта ориентирована на Астану.

В будущем проект должен позволять:

- добавлять новые города Казахстана;
- создавать отдельные карты посадок по городам;
- смотреть общую карту Казахстана;
- фильтровать деревья по филиалам и регионам;
- формировать единую национальную карту корпоративного озеленения Казахтелекома.

## 17. MVP

Минимальная версия продукта должна включать:

- локальный запуск через `index.html`;
- главную страницу проекта;
- условный вход по ФИО и табельному номеру;
- локальный файл с данными деревьев;
- интерактивный генеральный план или карту;
- кликабельные именные деревья;
- карточку дерева;
- счетчик посаженных деревьев;
- журнал проекта;
- базовый поиск.

## 18. Критерии готовности

Проект считается готовым для демонстрации, если:

- сайт открывается локально без сервера;
- все основные файлы находятся в папке проекта;
- данные читаются из локального файла;
- карта или схема отображает деревья;
- деревья кликабельны;
- карточки сотрудников открываются корректно;
- поиск по ФИО и табельному номеру работает;
- счетчик деревьев и статистика отображаются;
- дизайн выглядит экологично и связан с Казахтелекомом;
- проект можно показать руководству как концепцию инициативы.

## 19. Регистрация посаженного дерева

Сотрудник может заполнить форму после фактической посадки дерева. Форма собирает ФИО, табельный номер, должность, подразделение, город, дату посадки, вид дерева и примерное положение на генеральном плане. Сотрудник подтверждает соответствие возрастному условию инициативы. Повторная запись с тем же табельным номером не создается.

В статической версии сайта новые записи сохраняются только в хранилище браузера на устройстве сотрудника. Они сразу отображаются на карте и в журнале этого браузера. Запись можно скачать как JSON-файл для ручной передачи организатору. До отдельного добавления в файл проекта она не видна другим пользователям и не публикуется на GitHub Pages. Локальную запись можно удалить.
